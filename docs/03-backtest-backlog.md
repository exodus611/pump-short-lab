# Бэклог: калибровка порогов на собственном логе сигналов

Пороги в `config/per_exchange_thresholds.yaml` — стартовые (из литературы + живых замеров).
У бота уже есть 146 (MEXC) / 168 (BingX) / 158 (Gate) сигналов — это готовая база для калибровки.

## Шаг 1. Разметка сигналов
Для каждого сигнала из лога бота сохранить признаки на момент сигнала:
- `pump_pct` — амплитуда от часовой базы;
- `time_to_peak_min` — время от старта движения до пика;
- `speed_pct_5m` — скорость набора;
- `volume_z` — объём / средний (или ≥10× флаг);
- `funding` и интервал (4ч/8ч) на момент сигнала;
- `oi_growth_4h`;
- `long_short_users` (Gate);
- `depth_1pct`, `volume_24h` монеты на своей бирже;
- тип входа (market/limit), биржа, монета.

## Шаг 2. Разметка исходов
- win/loss, R-множитель, avgWin/avgLoss, время в позиции, причина выхода (TP/стоп/тайм-стоп).

## Шаг 3. Срезы (матожидание по каждому)
- быстрый vs средний vs медленный памп — по биржам;
- амплитудные корзины: +30–40 / +40–60 / +60–100 / 100+;
- funding-корзины и окно до штампа (особенно 4ч BingX: 30–90 мин до штампа);
- ликвидностные корзины (vol24, depth1%) — проверить гипотезу «мёртвый хвост MEXC съедает профит»;
- Gate: market vs (гипотетически) limit-вход, L/S > 2 vs ≤ 2.

## Шаг 4. Решения
- выключить/включить биржу или режим (Gate);
- зафиксировать пороги амплитуды/ликвидности/тайм-стопа по биржам;
- home-venue карта: проверить, что сигналы на «своей» бирже монеты дают лучшее матожидание.

## Шаг 5. Регресс контроля
После калибровки — прогон на последних N сигналах, не участвовавших в калибровке (walk-forward),
чтобы не переобучиться. Перекалибровка планово раз в квартал: прибыльность пампов со временем
падает (исследование NSF: −50–60% за полгода).
